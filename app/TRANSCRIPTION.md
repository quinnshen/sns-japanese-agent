# 第二阶段：Google 分批转写

本阶段读取第一阶段保存在本机的连续录音，准备识别窗口，保存 Google 日语转写和词时间，再汇总句子。GPT 翻译、括号假名和学习解析属于下一阶段；本阶段不调用 OpenAI。

**当前验收状态：第二阶段工程链路已通过，包括离线模块、真实 Google 识别、成功结果复用、增量回放，以及扩展 0.4.3 的 90 秒和 5 分钟实时全链路。录音与转写重叠执行已有本机持久化记录确认。**

## 三种独立单位

| 单位 | 当前设置 | 职责 |
|---|---|---|
| 浏览器上传 batch | 默认 5 秒，可调整 | 保存采集数据，确认接收后释放浏览器对应数据 |
| Google 识别窗口 | core 为 43 秒，左右各最多 1 秒上下文；单窗最多 45 秒 | 提供识别上下文和相对窗口的词时间 |
| GPT 文本批次 | 下一阶段设计 | 对完整句子及必要上下文翻译和解析 |

上传一个 batch 不会立即产生一次 Google 请求。单个 batch 不一定能独立解码，后端先按序验证、拼接连续容器，再解码成 **16 kHz、单声道、PCM16**。识别窗口从整数采样点切出 WAV，不按上传序号推算音频时间。

录音尚未结束时，只规划上下文已经就绪的完整窗口。录音完成后补齐最后一个窗口。左右上下文增加了重复送识别的音频，规划时会报告 `planned_audio_seconds`；它不是实际费用或账单上限。

2026-11-04，先前保存的本机素材完成后端独立真实 Google 验收：

| 素材 | 成功窗口数 | 累计请求音频时长 | 整理的句段数 | 再次运行新增请求 |
|---|---:|---:|---:|---:|
| 约 90 秒素材 | 3 / 3 | 94.18 秒 | 40 | 0 |
| 约 5 分钟素材 | 7 / 7 | 312.06 秒 | 120 | 0 |

90 秒录音的 18 个原始 batch 还按顺序回放到临时任务，使用已保存的 Google 响应验证增量处理，最终句子与完整录音处理完全一致；这次回放没有新增云端请求。
上述验收确认链路和存储行为，句段仍可能包含 ASR 错误。两份素材均保留了文本与词信息不匹配的警告，首个词早于首次播放观测的情况保留为未确定视频时间，未伪造精确对齐。

## 默认离线，显式启用付费处理

默认配置：

```dotenv
ENABLE_CAPTURE_TRANSCRIPTION=0
ENABLE_LEGACY_PIPELINE=0
ENABLE_ENRICHMENT=0
```

`ENABLE_CAPTURE_TRANSCRIPTION=0` 时，采集接口保存音频，不自动调度 Google。旧整段转写和 GPT 开关分别保持为 0。

以下命令从仓库根目录运行，假设已按项目说明创建 `app/backend/.venv`。将 `YOUR_CAPTURE_ID` 换成本机已保存的任务 ID。代码示例仅包含占位值，不包含真实素材地址或账户信息。

### 1. 离线准备与复用

```sh
CAPTURE_ID="YOUR_CAPTURE_ID"
app/backend/.venv/bin/python app/backend/capture_transcribe_cli.py \
  "app/data/captures/$CAPTURE_ID"
```

此命令默认不调用 Google，不加载 ADC。它验证已确认保存的连续 batch 前缀、准备本机 PCM、规划窗口、复用已经保存的结果并写入状态。

- 尚无可用音频时，状态为 `waiting_for_audio`。
- 已准备好窗口但没有启动识别时，通常为 `prepared`。
- 重复执行不会重复解码未变化的输入；缓存仍会做完整性检查。
- 正在录制的前缀仍然是未完成数据，不会被提升为完整采集。
- `aborted` 任务不自动进入本阶段；不能通过修改清单把失败素材冒充完整录音。

### 2. 主动执行少量真实 Google 请求

先配置使用者自己的 Google 项目和本机 ADC。项目设置保存在被忽略的 `.env.local`，ADC 留在仓库外；不要把凭据 JSON、令牌或账户密码复制进代码或提交。

下面的 `--run-google` **明确启动真实云端识别，可能产生费用**：

```sh
app/backend/.venv/bin/python app/backend/capture_transcribe_cli.py \
  "app/data/captures/$CAPTURE_ID" --run-google --max-new-requests 1
```

先检查这一个新请求的结果，再决定是否继续。已确认成功的窗口直接复用。下一次仍可使用相同命令，最多新增一个请求。

`--max-new-requests N` 限制本次 CLI 新发请求数，范围为 1–50；省略时默认 50。它不限制项目总费用，也不消除重复请求的计费可能。CLI 的 `--run-google` 是独立、显式的启用入口，不受服务器自动调度开关为 0 的阻止。

当前识别配置为 Speech-to-Text V2、`global`、`long`、`ja-JP`，启用词时间和自动标点；不区分人物。模型、地区和语言支持以 [Google 官方语言表](https://docs.cloud.google.com/speech-to-text/docs/speech-to-text-supported-languages) 为准。

项目将单窗限制在 45 秒、10 MB 以内。Google 当前同步 `Recognize` 的上限是 1 分钟或 10 MB，以先达到者为准；项目使用更短的窗口。[Google 内容限制](https://docs.cloud.google.com/speech-to-text/docs/quotas)

## 保存、恢复和重试

每个窗口分别记录输入指纹、状态、尝试次数和成功结果：

| 状态 | 含义与处理 |
|---|---|
| `queued` | 尚未发出请求 |
| `in_flight` | 已持久记录即将发出的尝试，等待确认结果 |
| `succeeded` | 原始转写结果已保存，后续复用 |
| `failed` | 收到明确拒绝或判定未发送；修正原因后可主动重试 |
| `unknown` | 请求可能已被处理，但本机没有可靠结果；停止自动推进 |

SDK 层关闭自动 RPC 重试，应用也不会盲目重发 `unknown`。成功结果先写本地文件，再标记 SQLite 成功；重启后若发现完整结果，可恢复成功状态。若只有未结束的请求记录，则标为 `unknown`。

总任务遇到阻塞窗口时显示 `needs_attention` 和 `blocked_windows`。先检查安全错误码与窗口序号，不要将完整 SDK 异常、配置内容或原始终端日志贴进公开 issue。

只有在确认接受潜在重复费用后，才显式重试结果未知的窗口。下面的 `0` 是从零开始的窗口序号，应替换成状态里需要重试的序号：

```sh
app/backend/.venv/bin/python app/backend/capture_transcribe_cli.py \
  "app/data/captures/$CAPTURE_ID" --run-google --max-new-requests 1 \
  --retry-window 0 --accept-duplicate-cost
```

每个窗口最多 **3 次尝试**，包括首次请求。达到上限后不会继续自动重试。请求发出后无法保证取消云端处理；本机超时、进程退出或关闭自动调度开关，都不代表该请求没有产生费用。

## 后台调度与本机接口

准备好做真实云端验收后，可在本机配置或启动环境中显式设置：

```dotenv
ENABLE_CAPTURE_TRANSCRIPTION=1
ENABLE_LEGACY_PIPELINE=0
ENABLE_ENRICHMENT=0
```

开启后，保存 batch、开始时间和完成清单的操作会唤醒后台转写任务。连续音频及上下文就绪后即可识别，因而可以与后续录音重叠执行；每个识别窗口仍独立保存结果。
新版扩展会明确提示 Google 处理已启用，并在采集期间和采集结束后查询转写进度、句段数。这个阶段只显示状态计数，学习用的括号假名和翻译解析由下一阶段展示。
运行中关闭开关会阻止后续窗口派发；已经发出的请求仍需等待结果。另一进程占用任务锁时，调度器最多等待 150 次、每次 1 秒，仍占用则保存错误状态，稍后可重新调度。

| 本机接口 | 用途 |
|---|---|
| `POST /captures/{id}/transcription`，JSON `{}` | 显式调度已有任务；只有转写开关为 1 时允许，可能发出真实 Google 请求 |
| `GET /captures/{id}/transcription` | 查询转写状态和已保存 `result`，查询本身不触发识别 |

这些接口继续使用现有 loopback Host／Origin 边界，不对外托管。`/health` 的 capability 表示功能开关状态，不代表云端识别已经验收通过。

## 词、句子与时间轴

- Google 词时间相对各自识别窗口，先加上 `audio_start_sec` 得到连续音频时间。
- 词按时间中点归入唯一 core。只对相邻窗口中原词一致、时间重叠且漂移很小的候选做一对一去重；同一窗口内的真实口语重复保留。不同词或不同分词不擅自猜成相同结果。
- ASR 原始文本保留在窗口结果和 `raw_transcripts`。有文本但缺少词时间、词与文本不匹配时，写入 `warnings`／`unmapped_results`，不悄悄改写或丢弃原文。
- Google result 或窗口结束不直接成为句子边界。按实际标点或后继约 1.2 秒间隔整理句子，未完成尾句保留为 `pending_sentence`。
- 只有整个采集和识别完成后，才可将无终止标点的尾段以 `boundary_reason: capture_end` 收尾；它表示素材结束，不保证语义完整。
- `audio_start`／`audio_end` 是音频秒；兼容学习界面的 `start`／`end` 是观测映射后的视频秒。首播前或缺少可靠观测时，视频时间可能为 `null`，同时给出警告。
- 时间映射使用录音开始、实际 `playing`／`waiting` 以及播放器位置；不拿 batch 序号或录制总时长比例替代对齐。浏览器墙钟观测不是精确音频 PTS，短暂缓冲和时间漂移仍可能造成误差。

自动标点和去重都是工程上的整理依据，不是语义或识别准确性的保证。跨窗漏字、识别分歧和人工选区截断的句子，需要在真实素材验收时检查。括号假名、自然中文和 ASR 存疑解析由第三阶段生成。

## 本机产物与 Git 隐私边界

产物位于 `app/data/captures/YOUR_CAPTURE_ID/transcription/`，整个 `data/` 被 Git 忽略：

- 本机连续音频准备缓存、PCM 与音频元数据。
- `state.sqlite3`：窗口和请求尝试状态。
- `windows/`：每个成功窗口的原始 ASR 文本、词时间和输入指纹。
- `result.json`：合并词、句子、pending、原文和警告。
- `status.json`：安全状态摘要。

录音、ASR 台词、素材来源和运行数据库都可能含个人信息，不能复制进测试 fixture 或公开文档。窗口公开配置与诊断不保存项目 ID、ADC 或 API Key；实际云端请求使用操作者自己的凭据和配额项目。真实识别会把对应音频窗口交给 Google，因此需与纯离线准备区分。
